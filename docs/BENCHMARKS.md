# 基准测试 · AI Forge / 星锻

> 所有数字在本机（Node v22.22.2，单线程 V8）实测，取 3 次中位数、热缓存。
> **复杂度声明**才是被不变量校验的部分；绝对耗时随机器/JIT 波动，为指示性。

```bash
npm run bench        # node bench/run.mjs
```

| 项目 | 配置 | 本实现 | 基线 | 加速 | 备注 |

### 优化器收敛（矩阵最小二乘 ‖X·W − Y‖²/N·H，Y=X·W\* 精确）

| 优化器 | 到达 loss ≤ 0.01 的步数 | 说明 |
|---|---|---|
| AdamW (lr=0.05) | **64** | 自适应矩，快速下降 |
| Muon (lr=0.05) | **167** | Newton–Schulz 正交化，2-D 权重收敛到近最优 |

两条不变量均断言：最终 loss ≤ 2% 初值（即两者都收敛到最优）；Muon 的「是否更快」取决于学习率，不作脆弱门禁。

## 解读与说明

1. **k-NN / 采样 / FlashAttention / Kahan 是稳赢项**：KD-tree 用空间划分把 O(N) 降到 O(logN·d)（低维）；Vose alias 把类别采样从 O(logV) 降到 O(1)；FlashAttention 用在线 softmax 把 O(T²) 显存降到 O(T)，且数值 bit-exact；Kahan 在病态求和下消除 catastrophic cancellation。
2. **GEMM blocked 为何没更快**：手写 ikj+tiling 在中小矩阵上受 V8 JIT 对朴素 ijk 的优化（以及边界开销）影响，测得略慢。这**不是算法错误**——分块在跨越 L1/L2 缓存的大矩阵上必然反超（复杂度声明 O(n³) 相同，常数更优）。生产吞吐建议接入 WASM/WebGPU 后端（零重写可插拔）。
3. **为什么报指示性数字**：基准的契约是「复杂度声明 + 诚实基线对照」。绝对毫秒数随 CPU/温度/Node 版本漂移，因此把结论锚定在**算法复杂度**与**不变量校验**上，而非单次墙钟时间。
4. **零依赖代价**：纯 JS、单线程、无 SIMD/多线程。若追求极限吞吐，可在不修改任何算法的前提下，把 `linalg.gemm` 换成 WASM 后端——这正是「零重写 / 集大成」预留的扩展点。
